## 2026-08-26 Separate Error Profile Workflow

Current path layout:

- Original RobDP uses the shared profiles under `/data/robdp/imdb-error-profile-0826` for every fold.
- Fold ownership CSVs are under `/data/robdp/imdb-separate-ep-0826/folds`.
- Newly generated profiles are under `/data/robdp/imdb-separate-ep-0826-1` and `/data/robdp/imdb-separate-ep-0826-2`.

Current file structure above:

- `0A`: run original PostgreSQL with `EXPLAIN ANALYZE` and save baseline runtimes.
- `0B`: run RobDP directly with `EXPLAIN ANALYZE` and save RobDP runtimes.
- `0C`: run RobDP final-level hint export with `EXPLAIN` only; this produces last-level candidate hints.
- `0D`: run the 13 original Reqo GUC candidates with `EXPLAIN` only; this produces Reqo-GUC hints.
- `1A/1B`: insert exported hints into original SQL and build hint SQL CSVs.
- `2`: execute hinted candidate SQLs once with `EXPLAIN ANALYZE` and save raw plan caches with runtime labels.
- `3`: build shared fold ownership CSVs.
- `4`: encode each fold from the raw plan cache; train computes normalization stats and test reuses them.
- `5`: train Reqo on another machine with the pre-split datasets.
- `6`: summarize runtime and winner statistics on another machine.

For separate error profiles, the order changes:

- Build shared fold membership first.
- Build one error profile per fold from that fold's own queries.
- Run RobDP/RobDP-last-level with the fold-specific error profile.
- Build hint SQL CSVs, plan caches, and encoded datasets for each fold.
- `0A` and `0D` do not use error profiles, so they can be shared globally.
- `0B` uses the original shared error profile under `SQLS_DIR`, not the fold-specific profiles.
- `0C` runs once per fold and uses that fold's error profile.
- This workflow is intentionally 2-fold only. The scripts now error out if fold
  count/fold id is not compatible with 2-fold mode.
- In the fold CSVs, `fold_N` is an ownership file: it contains only the queries
  owned by fold N. It does not contain train/test rows.
- To run "train on fold 1, eval on fold 2", build the profile from
  all rows in `robdp_fold_1.csv`, run `0C` with that profile, and materialize
  `fold_sql` with `--fold-id 2`.

Fold CSV schema:

| Column | Meaning |
| --- | --- |
| `fold_id` | The fold that owns this query. All rows in `robdp_fold_N.csv` have `fold_id=N`. |
| `global_query_idx` | Stable query index over the canonical `(template_id, original_query_id)` order. |
| `fold_query_idx` | Local index inside this ownership fold. |
| `query_group_id` | Query group id used by Reqo encoding/dataset files. |
| `template_id` | IMDb template id. |
| `original_query_id` | Query id inside the IMDb template. |
| `candidate_count` | Number of candidate SQL/hint rows for this query/source. |

When a runner receives `--fold-id` under this ownership schema:

| Runner option | Query files used |
| --- | --- |
| `--fold-split test` | Only `robdp_fold_${fold_id}.csv`. |
| `--fold-split train` | Only the other fold, `robdp_fold_$((3 - fold_id)).csv`. |
| `--fold-split all` | Both `robdp_fold_1.csv` and `robdp_fold_2.csv`. |

Old fold CSVs with `split`, `eval_fold_id`, `train_fold_id`, or
`query_fold_id` must be regenerated. The current scripts reject them.

Error profile usage:

| Step | Uses error profile? | Profile source | Notes |
| --- | --- | --- | --- |
| `3` | No | None | Builds the shared 2-fold ownership CSVs. Use query granularity for separate error profiles. |
| `9` | Writes profiles | `${BASE}-${fold}` | For fold N, read every row from `robdp_fold_N.csv`; those are fold N's own queries. |
| `0A` | No | None | Original PostgreSQL baseline runtime. |
| `0B` | Yes | Global shared profile under `${SQLS_DIR}` | RobDP direct runtime keeps the original/global error profile, not the fold-specific one. |
| `0C` | Yes | `${BASE}-${train_fold}` | Last-level candidates are generated under the training fold's own error profile. |
| `0D` | No | None | Reqo-GUC hint generation uses original PostgreSQL settings only. |
| `1A` | Indirect | Inherited from `0C` outputs | Builds RobDP hint SQL CSVs from plans already generated with the fold-specific profile. |
| `1B` | No | None | Builds shared Reqo-GUC hint SQL CSV. |
| `2A` | No | None | Executes shared Reqo-GUC hinted SQL and stores runtime labels in the cache. |
| `2B` | Indirect | Inherited from `1A` SQL | Executes RobDP candidates produced with the fold-specific profile and stores runtime labels. |
| `4A` | No | None | Combines ownership folds into train/test SQL using the existing fold membership. |
| `4B` | No direct use | Uses caches from `2A/2B` | Encodes from raw plan caches; labels already reflect the candidate source. |
| `5` | No direct use | Encoded datasets only | `reqo_fold_2` means train fold 1 and eval fold 2; `reqo_fold_1` means train fold 2 and eval fold 1. |
| `6` | No direct use | Runner/training outputs only | Summaries inherit the effect of whichever profile created the candidates. |
