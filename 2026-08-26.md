## 2026-08-26 Separate Error Profile Workflow

Current file structure above:

- `0A`: run original PostgreSQL with `EXPLAIN ANALYZE` and save baseline runtimes.
- `0B`: run RobDP directly with `EXPLAIN ANALYZE` and save RobDP runtimes.
- `0C`: run RobDP final-level hint export with `EXPLAIN` only; this produces last-level candidate hints.
- `0D`: run the 13 original Reqo GUC candidates with `EXPLAIN` only; this produces Reqo-GUC hints.
- `1A/1B`: insert exported hints into original SQL and build hint SQL CSVs.
- `2`: execute hinted candidate SQLs once with `EXPLAIN ANALYZE` and save raw plan caches with runtime labels.
- `3`: build shared train/test folds and fold-specific SQL CSVs.
- `4`: encode each fold from the raw plan cache; train computes normalization stats and test reuses them.
- `5`: train Reqo on another machine with the pre-split datasets.
- `6`: summarize runtime and winner statistics on another machine.

For separate error profiles, the order changes:

- Build shared fold membership first.
- Build one error profile per fold from that fold's train split only.
- Run RobDP/RobDP-last-level with the fold-specific error profile.
- Build hint SQL CSVs, plan caches, and encoded datasets for each fold.
- `0A` and `0D` do not use error profiles, so they can be shared globally.
- `0B` should usually run the fold's test split only.
- `0C` should usually run train+test for that fold, because `train_no_split.py` needs candidate labels for both sides of the same fold/profile experiment.
